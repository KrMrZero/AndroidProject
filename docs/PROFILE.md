# Профиль: карта работ и разделение ответственности

Документ описывает, кто какие файлы ведёт и что осталось доделать.
Каркас уже собран: экраны отрисовываются, данные читаются из Firestore,
навигация из `MainActivity` подключена, сборка проходит.

## Файлы и зоны

| Зона | Файлы | Кто ведёт |
|---|---|---|
| Профиль | `ui/profile/ProfileScreen.kt`, `ui/profile/ProfileViewModel.kt` | человек 1 |
| Редактирование профиля | `ui/profile/EditProfileScreen.kt`, `ui/profile/EditProfileViewModel.kt` | человек 2 |
| Уведомления | `ui/profile/NotificationsScreen.kt`, `ui/profile/NotificationsViewModel.kt` | ведётся нами, см. [`docs/NOTIFICATIONS.md`](NOTIFICATIONS.md) |
| Общие компоненты | `ui/profile/ProfileComponents.kt`, `ui/profile/ProfileBottomNavigation.kt` | заморожены, менять только по согласованию |
| Интеграция | `MainActivity.kt`, `ui/components/CoFlowNotificationBell.kt` | аккуратно: файлы правят и другие люди |

Зоны специально разделены так, чтобы человек 1 и человек 2 не пересекались
по файлам. Общие файлы нужны обоим, поэтому их лучше не трогать без договорённости.

## Что уже работает

- Загрузка имени и почты из `users/{uid}`.
- Карточка профиля перечитывается при возврате с экрана редактирования.
- Выход из аккаунта.
- Удаление аккаунта с подтверждением и вводом пароля.
- Сохранение имени и почты в Firestore.
- Переходы: профиль ↔ задачи ↔ проекты, профиль → редактирование, профиль → уведомления.
- Колокольчик ведёт на экран уведомлений.
- Уведомления хранятся в Firestore и приходят из `NotificationRepository`.
- У каждого экрана есть `@Preview` — можно смотреть UI без Firebase.

## Зона «Профиль» — задачи

1. **Тёмная тема**
   - строка временно убрана из UI, чтобы не показывать неработающий переключатель;
   - при реализации: сохранять выбор (DataStore или поле пользователя);
   - прокинуть флаг в `CoFlowTheme` в `MainActivity`;
   - решить, нужен ли режим «как в системе».

2. **Смена пароля**
   - нужен метод в `AuthRepository` (см. раздел про слой данных);
   - диалог: текущий пароль, новый пароль, повтор;
   - валидация длины и совпадения, понятные ошибки;
   - повторная аутентификация перед сменой.

3. **Переключатель уведомлений**
   - строка временно убрана из UI;
   - если возвращать — сначала решить, где хранить настройку и как её учитывать.

4. **Реальный счётчик непрочитанных**
   - уже реализован в зоне уведомлений: `MainActivity` передаёт `hasUnread` в экраны.
   - самостоятельно ничего считать не нужно — используйте параметр `hasUnreadNotifications`.

5. **Аватар (опционально)**
   - поле в `UserModel`, загрузка в Firebase Storage, отображение в карточке;
   - без этого оставить иконку.

6. **Строки**
   - вынести подписи экрана и диалога удаления в `strings.xml` и `values-en`.

## Зона «Редактирование профиля» — задачи

1. **Синхронизация почты с Firebase Auth**
   - сейчас `UserRepository.updateUser` меняет только `users/{uid}`;
   - нужен `AuthRepository.updateEmail(newEmail)` с повторным входом;
   - порядок: сначала Auth, потом Firestore (или с откатом), чтобы не было рассинхрона.

2. **Имя**
   - дополнительно обновлять `FirebaseUser.displayName`;
   - ограничить длину (например, 2–50 символов) и обрезать пробелы.

3. **Проверка почты**
   - `UserRepository.getByEmail` уже есть — можно проверять занятость;
   - при смене почты желательно отправить письмо подтверждения.

4. **Обновление профиля на главном экране**
   - сейчас профиль перечитывается при открытии экрана;
   - если нужно обновление «сразу», согласовать общий источник состояния.

5. **Строки** — так же вынести в ресурсы.

## Контракты экранов

Сигнатуры `Route`/`Screen` — точки стыковки с `MainActivity`.
Менять их можно, но нужно предупредить того, кто отвечает за интеграцию,
иначе сломается навигация.

- `ProfileRoute` — колбэки: задачи, проекты, уведомления, редактирование, смена пароля,
  удаление аккаунта завершено, выход.
- `ProfileScreen` — принимает состояние и колбэки, ничего не навигирует сам.
- `EditProfileRoute` — назад, сохранено, уведомления, вкладки нижнего меню.
- `EditProfileScreen` — состояние + колбэки полей и сохранения.
- `NotificationsRoute` — назад, вкладки нижнего меню.

Правило: UI-экран не знает про `NavController`. Вся навигация — в `Route` и `MainActivity`.

## Что понадобится в слое данных

Это не входит в каркас, обсуждать отдельно:

- `AuthRepository.updateEmail(newEmail)` — смена почты для входа.
- `AuthRepository.changePassword(currentPassword, newPassword)` — смена пароля.
- `AuthRepository.deleteAccount(password)` — уже реализовано.
- `UserModel.avatarUrl` — только если делаете фото.
- Уведомления (`NotificationModel`, репозиторий, правила, индексы) — уже реализованы,
  см. [`docs/NOTIFICATIONS.md`](NOTIFICATIONS.md).
- Правила Firestore: чтение/запись своего профиля, удаление своих `memberships`,
  доступ к своим уведомлениям.

## Правила работы

1. Каждый ведёт свои два файла; общие файлы — по согласованию.
2. Строки — в ресурсы, не хардкодить в новых местах.
3. Использовать готовые компоненты `CoFlow*` и элементы из `ProfileComponents.kt`.
4. Комментарии и тексты — на русском, как в остальном проекте.
5. Перед PR: `./gradlew :app:compileDebugKotlin`.
6. Если меняете сигнатуру `Route`/`Screen` — сообщите ответственному за `MainActivity`.

## Definition of Done

Экран считается готовым, когда:

- данные берутся из Firestore, а не из заглушек;
- есть состояния загрузки и ошибки;
- все действия сохраняются и видны после перезапуска;
- подписи вынесены в ресурсы;
- сборка проходит;
- обновлён этот документ, если менялись контракты.
