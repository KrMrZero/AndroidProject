## Правила

Договорённость: заголовок коммита оформляем по формату Conventional Commits.

Формат заголовка:
```text
тип(тг#номер_задачи): что сделал
```

Пример:
```text
feat(тг#2): добавил команду /start
```

Основные правила:
1. **Первая строка — заголовок коммита.**

   Формат: `тип(тг#номер_задачи): что сделал`.

3. **Все задачи нумеруются в Telegram.**

   В скобках указываем номер задачи из Telegram, например `тг#2`. Номер задачи – это не номер
   коммита. Если в одной задаче делается несколько коммитов, во всех указывайте один и тот же номер
   задачи.

5. **Пишем, что уже сделал.**

   В заголовке используем прошедшее время: «добавил», «исправил», «вынес», «обновил», «описал».
   Не пишем в инфинитиве или как задачу: «добавить», «исправить», «сделать».

7. **После заголовка можно добавить описание.**

   Между заголовком и описанием — пустая строка.
   В заголовке — суть, в описании — что и зачем сделал.

9. **Мелкие правки можно без номера задачи.**

    Если изменение совсем крошечное и не привязано к задаче, номер можно не указывать (например,
   `docs: опечатка в README`). В остальных случаях – номер обязателен.

   Следовать этому большую часть времени не нужно. Если лид решит что-то поменять, то он пишет
   коммит, исходя из этого правила (изменение маленькое). В ином случае пишет для себя задачу
   конкретную в тг и затем нумерует.
   
11. **Тип коммита — коротко и по смыслу:**

   | Тип | Когда использовать |
   |---|---|
   | `feat` | новая функциональность |
   | `fix` | исправление |
   | `docs` | документация |
   | `refactor` | рефакторинг без изменения поведения |
   | `test` | тесты |
   | `chore` | служебные изменения |
   | `style` | форматирование/стиль без изменения логики |

   

## Примеры хороших коммитов

Короткие:

```text
feat(тг#2): добавил команду /start
fix(тг#2): исправил обработку пустого сообщения
docs: описал правила коммитов
refactor(тг#2): вынес отправку сообщений в сервис
test(тг#2): добавил тест на напоминания
chore: обновил зависимости
```
Все промежуточные коммиты по одной задаче должны содержать один и тот же номер.

C описанием:

```text
feat(тг#2): добавил напоминания

Добавил команду /remind. Напоминание сохраняется в БД
и отправляется по таймеру.
```

## Чего делать не надо

Не писать так:

```text
добавить напоминания
fix(тг#2) исправил баг
feat: добавил напоминания #2
```

Правильно:

```text
feat(тг#2): добавил напоминания
fix(тг#2): исправил баг
```

## Как коммитить в консоли

Коротко:

```bash
git commit -m "feat(тг#2): добавил напоминания"
```

С описанием:

```bash
git commit -m "feat(тг#2): добавил напоминания" -m "Добавил команду /remind. Напоминание сохраняется в БД и отправляется по таймеру."
```

Либо просто:

```bash
git commit
```

Откроется редактор по умолчанию. В нём:

- первая строка — заголовок;
- пустая строка;
- дальше — описание.


## Как написать задачу для вашей команды в tg

Если вам нужно создать задачу для команды, пишите её так:
```text
тг#номер_задачи: описание задачи
```
Исполнитель сам решит к какому типу задач это относится.
